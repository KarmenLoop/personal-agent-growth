# 任务记录

[English](task-record.en.md)

优先复用任务已有记录。小任务用一份 Markdown 或运行回执 JSON 即可，内容的用途比文件数量重要。采用 Markdown 学习模式时，学习事实与结论只以 MD 为真相，JSON 仅保留原始运行证据。

记录至少包含以下关系：

| 对象 | 关键内容 |
|---|---|
| 目标 | ID、版本、用户希望的结果、完成依据、范围 |
| 证据 | ID、来源、实际观察、时间、覆盖范围 |
| 认识 | ID、版本、解释、支持与冲突证据、条件 |
| 决定 | ID、目标版本、采用的认识版本、候选、选择、预测、改判条件 |
| 行动 | 对应决定、真实调用或动作、结果、证据位置 |
| 学习 | 触发事件、原因假设、修改对象、验证和适用边界 |
| 联系 | 需要用户决定什么、相关问题、是否已回答、可继续的独立工作 |
| 接续 | 下一条件、责任方、状态、实际后端标识或尚未登记 |

动作前固定重要预测；结果出现后追加观察和修正。事后补记标明补记，引用原始工具或用户记录，不能当作预先预测。

一次工具失败，至少说明哪个阶段尚未达到。检查器没有成功启动时，待检查对象的结论仍未知。

验证记录附带：目标 ID 或路径、内容版本或校验值、执行环境、实际命令或工具输入、到达阶段、退出状态、原始输出位置、结论范围。换对象或版本时重新判断旧结果是否仍适用；历史失败不自动归属新候选。

共享或接手任务时，给出当前有效目标、决定与结果的索引。通用 skill 包携带方法；同一用户的任务状态和联系配置通过单独的获准任务材料或共享库提供，不能假定复制 skill 就同时迁移了这些状态。

记录引用使用任务内相对路径，绝对位置放在宿主配置中。分享 skill 包时不把实际用户记录、工具凭据或本机运行环境一起带入。

“学习到方法”需要指向实际来源或结果；同一来源的摘要不算新增独立证据。
