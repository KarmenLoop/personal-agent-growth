# 日、周与项目的 Markdown 学习协议

[English](markdown-learning.en.md) · 版本 0.4.1

当用户要求学习记忆、项目中断恢复、画像证据、日周复盘或次周预习时使用。完整目录、全部格式、评分与注入伪代码见 [Markdown 学习体系](../docs/markdown-learning.zh-CN.md)；模板见 [模板索引](../templates/learning/README.md)。

1. 使用用户明确的学习根目录。已有 policy 先读，不重建另一份知识库；Koder 原生候选默认 ~/.koder/learning，不假定其他宿主已安装原生命令。
2. 任务恢复必须先读项目 context 和最新有效 node，再读 memory 的约束与决定。核对稳定项目 ID、修订、实际产物和 writer。用户新指令优先，修订冲突不能覆盖。
3. 学习语义以 Markdown 为唯一真相。原始工具回执和冻结实验可保留原格式，但 MD 记录必须引用它们。旧 SQLite 交接或 JSON 经验索引不同时成为当前项目和画像的另一个可写权威；迁移要显式切换。
4. 重要决定及时补 memory，停顿必写 node 并刷新 context。原始聊天不整段塞入 memory。完成依据全部满足后再写 summary，拆出带来源的可迁移经验，更新 index done。
5. 有活动的日期写 daily，并给活动项目补节点。周结读全部本周日报；次周一读上周周报，检查实际应用、薄弱点与下期预习。缺覆盖写未知，重复触发无新事实不重写。后台运行依赖真实宿主调度，不由文件生成产生。
6. 行为只取授权可观察的任务信号，带时间、来源、支持/反对和纠正链。禁止贬义人格标签。Agent 失败单独归因。明确偏好立即在其范围内生效；推断标签按公开评分公式计算，低置信或冲突不强规划。
7. 撤回/纠正来源后复核所有依赖标签、经验、summary 与计划。旧记录保留并标失效/替代，不悄悄擦掉失败。
8. 检索先过滤来源有效性、适用范围、弃用状态，再按领域、失败机制、近期性排序。每次留下实际读取路径与修订/哈希。必需 context/node/约束优先于可选经验，超预算明确处理，不默默丢约束。
9. 自学从下一用途出发，查一手资料、记录来源与限制，先存 untested；在原任务和有意义变式中应用后才升级 local/reused。建立链接可定位到事实，不能把一页摘要当独立多来源。
10. 保留旧版本与失败。完整规则、标签阈值和案例见详细契约；本入口不替代宿主权限、真实 Agent 结果或调度回执。
