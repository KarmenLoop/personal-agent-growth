# Windows Agent 中断后接续

[English](windows-agent-continuation.en.md)

## 场景

通过真实 Windows CLI Agent 接续共享 Markdown 项目，补齐普通权限下的安装或文件操作依据。启动器只负责输入任务和保存回执；模型必须实际选择工具、读取资料、执行与写回。

## 做法

先恢复 context、最新 node 和长期约束，核对未完成操作。用现有可信令牌、输入哈希与原始回执确定最小未知；不要在每次恢复时重复整套环境扫描。读完直接影响下一动作的资料就先落盘预测、验收条件和失败后继，再执行关键动作。为预习设置停止条件：新增资料不会改变下一步时就开始验证。

Windows 命令必须对应实际 shell。复杂表达式使用本工作区的可审阅脚本；需要可见错误和退出码，避免用错误抑制制造成功外观。若宿主返回 `SHELL_RECONCILIATION_REQUIRED`，保留原调用编号、原因、清理状态和输出，使用允许的只读工具核实影响。不要重复受阻命令或切换工具重放。只在结果已核实、当前回合结束且已有授权允许继续时，发起处理剩余工作的后续回合；宿主明确要求用户操作时仍须遵守。

区分提供方输出、公开回复和经验记录。自动摘要只保存公开回复与可复核事实；先分离协议思考块再截短，保留代码示例中的字面标记。原始协议回执保留在受控证据目录，不复制进长期语义记忆或公开报告。

调用记忆工具前核对实际契约。Koder 的 `learning_read open` 使用文首元数据 ID，而非文件路径；`learning_write experience` 的 `evidence` 必须是读取返回的来源对象数组，包含 `document_id` 与 `excerpt_sha256`，须原样复制完整对象，不自行添加字段。`anchor` 只能是工具返回的行为事件 ID，不能填写 Markdown 标题；保留已有读取范围字段。优先 `learning_read open` 不可变节点并引用其返回的 `source`。叙述性证据写进 `why`、`steps` 或 `pitfalls`，来源优先选不可变节点。`decision` 与 `checkpoint` 会更新 memory/context，旧哈希随即失效；完成写入后重新读取节点，再单独保存经验或完结记录，不把这几种操作与旧引用放在同一批调用中。`complete` 不引用本项目 memory/context，以免完结动作使自身证据失效。遇到 `LEARNING_SOURCE_CHANGED`，先重读并判断原结论是否仍成立，不能编造哈希或反复提交旧引用。写入失败不等于已经沉淀经验；交接前核对返回路径并读回 Markdown。Agent 写入的经验仍为 `untested` 候选，由独立验证决定是否升级。


恢复时只读取明确相关的 context、最新 node、memory 与回执文件，禁止为定位已知文件递归列出整个学习目录。先确认文件工具能访问的工作区边界；共享记忆绑定不等于授权读取另一个工作区。若原始回执无法直接读取，协调器可在既有授权范围内交接明确列出的原始文件，记录源路径、字节数与哈希；接收 Agent 独立验证交接副本，公开说明原始文件和交接副本的区别。不得复制整个记忆库来冒充同根接续。输出超限或进程状态不明时保留原回执、核查进程与已发生的效果，结束该回合后仅接续剩余工作；不得扩大输出或权限限制来掩盖错误。

当收尾阶段反复偏离到环境扫描时，应收窄本轮工具面，保留真实模型和相同步骤上限。具备相应候选运行时的 Koder 可显式选择 `--harness learning-review`：只开放已知文件读写、Skill 和记忆工具，不提供 Shell、全目录搜索、浏览器或对外操作。此配置不适合执行阶段；需要运行新的检查时，另行选择与已授权任务相符的配置。先核实旧回合已结束和原操作影响，不借工具配置重放未知操作。环境参数应从命名的启动回执取得，不能为补教程扫描整个安装目录。

## 为何有效

显式读取项目包必须重新观察磁盘；写完 checkpoint 后检查返回的修订号与最新节点是否改变，不能沿用启动缓存。长文档按 `read_file` 的 `offset` / `maxBytes` 和返回的 `nextOffset` 顺序读到结尾，保持 UTF-8 字符边界；不以无变化替换冒充读取。清单中的源路径仅说明交接声明，不能单独证明原目录存在或程序执行；运行结论必须回到真实命令、输出及完成回执。发现旧经验含有这类错误时，新增纠正条目并通过 `supersedes` 保留旧条的废弃关系，再重新完成限定项目。

过长预检会消耗任务预算，并可能引入与目标无关的失败。错误类别应来自实际回执，而不是模型对“权限”“安全”等词的猜测。保存预测后执行，才能比较原判断和真实结果；只保存模型结论不能证明学习发生。

## 反例/坑

- SYSTEM 通过不能推导普通权限通过。记录有效令牌、完整性级别和提升状态；过滤后的管理员令牌与独立标准账户分别说明。
- 新进程不是新记忆：两个会话需要绑定同一物理 Markdown 根目录和项目 ID。新工作区接续时不能把旧聊天或整份知识库粘进提示词冒充恢复。
- `exit 0`、工具调用次数、生成摘要都不是任务质量结论。审阅真实产物、原始输出、来源和剩余缺口。
- 原失败回合必须保留。新成功只覆盖已复验条件；模型用量是提供方返回值，费用未知时写 unknown，不填零。

## 可复制步骤

1. 记录会话、工作区、项目、记忆根、Skill 哈希、模型、有效权限及输入身份。
2. 读取最小恢复包与直接相关资料，写预测后实际执行。
3. 逐项核对原始回执；修已定位问题，不降低权限或断言要求。
4. 保存事实、经验候选和带准确路径的暂停节点，结束第一会话。
5. 新会话换工作区但保留同一记忆根与项目。通过读取记录、修订号和前后文件哈希证明恢复；检查第一阶段产物，将经验应用到新交付物。
6. 更新下一动作与适用范围，完成或保留具体阻塞。没有明确未来工作时不创建定时任务。
