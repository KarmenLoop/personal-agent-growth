# Learning, validation, and contact

[中文](learning-and-contact.md)

## Preparation, remediation, review

Prepare backward from the next use. Before producing a skill, check the format and loading conditions needed for that package; collecting every host document is not the completion test.

Remediate an observed discrepancy. Preserve the failure stage and raw return, and retain alternative explanations. Fix an unmet environment requirement as an environment issue; revise a method when the method is at fault.

Review through variation: can the same mechanism be recognized in a different-looking problem, and can the agent stop applying it when conditions change? Distinguish replay, deterministic checks, independent Agent execution, and external outcomes.

## Skill changes

Preserve the previous version and its failures. A candidate identifies the changed selection rule, predicted benefit, and possible effects.

Check the repair on the original task and transfer/misuse on meaningful additional cases. Cases already used to develop a change are development cases. Record differences in model, tools, inputs, and budget rather than inventing improvement percentages.

Adoption is limited by task scope and configuration. Editing an isolated candidate does not update global installation or other projects.

## Contact

Before asking, check whether existing material resolves the issue, whether the user must choose, how their answer changes action, and which questions can be combined.

No reply means the answer is still missing. Continue independent authorized work and retain dependent actions as pending. Temporary preference assumptions remain scoped and cannot grant authority.

When the user prefers completion before contact, retain solvable findings in records and the delivery summary. Ask about choices that matter. Routine tool progress and opening a new topic are separate acts.

For future work, preserve purpose, expiry, trigger, read location, action, and completion criteria. Register and verify through a real host interface before claiming it is scheduled. In-turn waiting and subtask completion messages are not background wakeups.
