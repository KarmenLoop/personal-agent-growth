# 共享记忆与跨工具恢复

用于另一宿主接手任务、切换会话或读取共同知识库。方法可以共用；用户状态、凭据、执行权限和调度能力各自核实。

## 找到同一个任务

从交接给出的任务根目录和入口索引读取当前状态，不扫描用户全部历史。核对任务 ID、目标版本、状态修订、已完成阶段、当前待办、产物哈希和读写责任。旧任务的 completed 不代表新目标完成；旧任务的未验证项也不覆盖后来取得的证据。

任务记忆至少应能表达：

```json
{
  "task_id": "task-specific-id",
  "goal_revision": 1,
  "state_revision": 1,
  "status": "ready",
  "phase": "next-useful-phase",
  "writer": "host-or-agent-id",
  "completed": [],
  "input_index": "inputs/index.json",
  "contact_policy": "memory/preferences.json",
  "next_action": "a concrete action and its completion condition",
  "schedule": {"owner_host": null, "backend_id": null, "status": "not_registered"}
}
```

优先复用已有字段与记录。事实、偏好、解释和候选经验保留来源、适用范围与失效条件；高频可用事实进入索引，其余按需读取。用户偏好来自明确表达；没有记录的习惯和私人属性保留未知。

## 一份内容，清晰的写入责任

同机时，两个宿主读取同一个任务目录；宿主发现目录可链接同一份 skill。记录解析后的真实路径与内容哈希，检查链接可访问，不以路径字符串相同认定实际共用。

跨设备时，需要已授权的同步或传输方式以及路径映射；本地绝对路径、凭据、会话句柄和运行许可不随文件自动迁移。

同一份可变状态由当前责任方串行写入。接手时读取 state_revision，提交前再读；已变更则合并真实新事实或等待归还责任，不能覆盖较新状态。交接时保存实际产物、检查回执、下一动作，再移交 writer 并递增 state_revision。写入后回读，防止“消息说完成但记忆仍旧”。

追加经验前读取已有记录并检查标识唯一性，优先用执行方前缀或唯一标识，不能凭上轮记忆猜下一个序号。发现重号时按来源和内容区分记录，保留纠正前快照与映射，只改冲突标识，不丢失任一事实。排队消息到达时重新核实当前 writer 和修订；纠正已经完成则跳过，不按消息发出时的旧责任重复写入。

另一工具必须实际读取入口、使用记忆完成任务并写回结果，发送交接消息本身不算恢复完成。验收方核对输入和输出身份，必要时实际复用产物。

验证接续时，在真实交还后写入一个有用途的新决定或反证，并递增修订。接收方下一次从这份记忆恢复，说明读取了哪个修订、哪些经验改变本次动作，再保存实际复习结果；仅沿用聊天上下文、重复旧结论不能证明读取了新记忆。任务记录与宿主调度分开存放时保存绑定入口和责任方，避免把“本执行方未登记”误写成“整个任务没有调度”。

## 匹配宿主能力

先查当前宿主可用接口。CLI 未登录、桌面已登录是两个不同状态；若已有获准的可用入口，可切换并记录，不复制凭据或假定登录通用。界面上的按钮、任务活动和生成面板只证明对应观察，不证明文件已保存或检查已运行。

skill 被显式读取、宿主自动发现、宿主自动选择、实际执行和结果有效分别留证。目录存在不证明自动选择；显式路径加载可作为接续方式，但标明这一事实。

目标宿主没有已核实调度接口时，把后续交回具备调度能力的责任方，并记录未登记状态。任务若已可立即完成，继续执行即可；不为演示跨工具而制造额外等待和会话。

## 离线包的判定

`scripts/verify_handoff.py` 接受当前包和指定 manifest，输出实际身份、环境和阶段。退出 0 表示一致；退出 1 表示发现归档问题；退出 2 表示调用、输入或限制导致未完成检查。脚本格式见真实 manifest。

完整性通过后，仍按当前用途检查资源引用、运行环境或实际行为。只有获得对应实际结果才能把“可读”“可用”“跨工具运行”记为已验证。
