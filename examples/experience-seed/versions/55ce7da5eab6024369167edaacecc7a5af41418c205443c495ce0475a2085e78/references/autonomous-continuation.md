# 自主唤醒与结果接续

用于确有未来工作的安排、定时恢复、改频和收尾。skill 提供判断规则，运行依赖宿主；先核实当前会话可调用的工具、登录状态与执行位置。

## 把待办变成可恢复任务

登记前保存：任务 ID 与目标版本、当前阶段、已验证产物及摘要、下一动作、检查依据、联系偏好、执行责任方、期限与运行上限。设置应取决于任务成本和目的，不沿用演练中固定的分钟数。

每次后续必须回答“等到那时有什么可做”。立即可做的工作现在完成；只有等待新输入、需要间隔复习、等候外部结果等情况才安排唤醒。使用实际后端登记，绑定任务与宿主会话，保留返回并回读配置。已有相关任务优先更新，避免创建重复调度。

区分以下证据：

| 状态 | 可作为依据的事实 |
|---|---|
| planned | 已保存目的与下一动作 |
| registered | 正式后端接受，ID、目标会话、状态和调度经回读确认 |
| triggered | 宿主实际发送的事件与对应会话回合；本地编号仅作索引 |
| executed | 实际工具调用、输入身份、产物、退出状态和原始输出 |
| verified | 下一阶段复用产物并核对达成条件 |
| stopped | 后端暂停或删除已核实，同时保存本地终态 |

文件时间戳、人工继续、子代理完成消息和单独的 ACTIVE 状态不能替代实际触发证据。

## 每次唤醒的动作

1. 先读绑定与当前状态，核实触发来源、任务版本、取消、期限、额度和执行责任。已完成或已取消的迟到触发直接核实停止状态，跳过重复工作。
2. 检查已有产物，再决定从哪一步恢复。若上轮动作已完成但状态未写完，按真实回执补全接续状态；遇到不明外部副作用，先查实际状态再决定是否重试。
3. 行动前保存关键预测。按本阶段需要预习、执行或复习；发生差异先归因到输入、方法、环境、权限或运行阶段，局部补足后回到任务检验。
4. 保存本次结果和剩余未知。根据结果选择继续、针对性补课、调整间隔、等待用户决定或结束；每个选择要有具体后继和停止条件。
5. 需要更新调度时实际调用后端并回读，再记本地安排已生效。结果验收通过后实际暂停或删除后端，回读成功后记 completed，避免周期空转。

后端更新已成功而本地写入中断时，以回读和原始返回修复状态，不再创建第二个任务。后端不可用时保留具体失败、可完成的独立工作和未登记的后续；只对必须用户决定的阻碍发问。

## 检查学习是否生效

预习从下个用途倒推，写下预测和适用条件；复习实际调用此前产物或方法，以变式检查能否迁移。保存“之前怎样判断、什么证据改变判断、改了什么、复验怎样”。重复陈述旧答案或多写文件不构成学习证据。

当前宿主负责调度、另一个工具负责执行时，分别记录两者的真实行为。接收方提出下一步不等于它已经登记定时器。原生调度与另一宿主的能力不能通过复制 skill 转移。

## 联系

沿用当前任务的用户选择。选择“仅需我决定时联系”时，自行解决并保存普通发现，合并必须取舍的问题；成功后的结果汇总与每轮主动通知分别处理。任务终止时保留最后事实和恢复条件，不以不断联系用户替代停止。
