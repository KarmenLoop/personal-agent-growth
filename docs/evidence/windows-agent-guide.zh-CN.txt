### 1.1 身份口径：过滤后的管理员令牌 ≠ 独立标准账户

| 口径 | 本轮是否覆盖 | 说明 |
|---|---|---|
| SYSTEM | **不覆盖**（仅历史对照） | `prior-system-receipt.json` 全 PASS 只说明 SYSTEM 下成立，不能外推到普通权限 |
| **过滤后的管理员令牌**（用户仍属 Administrators 组，但令牌中该 SID 为 deny-only；`elevated=false`、中完整性） | **覆盖** | 本指南全部实测结论只在这一条件下成立 |
| **独立标准账户**（不属于 Administrators 组的普通用户） | **未覆盖** | 本机没有该账户，本轮未取得结论；**不得用过滤后的管理员令牌结果代替它** |

## 5. 真实限制（本机证据边界）

1. **普通令牌不能创建文件符号链接。** 无 `SeCreateSymbolicLinkPrivilege`，Developer Mode `NOT_SET`，Node 报 `EPERM`（Windows 1314 `ERROR_PRIVILEGE_NOT_HELD`），栈顶 `fs.symlinkSync`（`node:fs:1885:11`）← `test/windows-acl-helper.test.mjs:19:85`。
2. **夹具由 SYSTEM 预置，不等于普通用户能建链接。** `fixture-provision.json` 自述 `purpose = "Fixture provisioning only; not non-elevated test acceptance"`，`identity = NT AUTHORITY\SYSTEM` 是**制备身份**，不是测试身份。
3. **已取得的产品结论是 7 项检查全部通过，不是 1 项**：在过滤后的管理员令牌下，original-four 4 条用例与 native-smoke 3 条用例合计 **7 项全部通过**（收尾运行：original-four `# pass 4 / # fail 0`、native-smoke `# pass 3 / # fail 0`）。其中「拒绝被重定向的 ACL 程序」只是 7 项中的**一项断言**：verifier 面对符号链接形式的 helper 路径时在 `lstat` 阶段返回 `false`，且 `run` 调用计数为 0（零执行），断言未被降级。**不要把这一项断言写成 7 项的全部结论**，也不要反过来用它否定其余 6 项；被测源 `windows-acl.mjs`（`606f2812…c948`）与 helper（`c4ba925e…4273`）字节未变。
4. **未取得结论**：普通用户能否自行创建该符号链接；Windows Cursor；**独立标准账户**；应用关闭后的唤醒。这四项都超出本机本轮覆盖范围，见第 7 节的触发条件。
5. **身份口径只到“过滤后的管理员令牌”。** 全部结论建立在 `elevated=false`、中完整性、Administrators 为 deny-only 的令牌上；独立标准账户与 SYSTEM 都不在其中（见 1.1）。
6. **Skill 参考文件经历过漂移与受控升级，而且快照会继续过期。**
   - 漂移事实（保留）：`runtime-repair.json` 记录 `references/windows-agent-continuation.md` = `694d026a3c8091cd5aa303e36e810f363cdcbf57ac4d8f2b6f061375213f6149`，B2 复习回合实测为 `9f9f5aee35a9494fd46374d6531c283067856d5ed053a12c00566b25f21f85e2`；`references/shared-memory.md` 仍为 `21f417d6…c7a`，SKILL.md 仍为 `284d2eb9…f46`。

## 6. 恢复规则（新会话必读）

1. **先恢复记忆，再动手。** `learning_read action=pack` 取回项目 pack；再用**文首元数据 id** 调 `learning_read action=open`（例如 `windows-user-continuation-context`、`windows-user-continuation-node-26`、`windows-user-continuation-memory`）。**`open` 的 id 不是文件路径**；用路径只会取不到。
2. **只读最小恢复包。** 只读 context、最新 node、memory 与直接相关的回执文件。**禁止**为了定位已知文件而递归列出整个学习根目录——这正是输出超限的原因。
3. **不把旧聊天或整份知识库粘进提示词冒充恢复。** 新会话必须真的读到修订号与文件哈希。
4. **跨工作区接续的三条不变量**：同一物理 Markdown 根目录、同一项目 id、同一 Skill 及其参考文件版本。共享记忆绑定**不等于**授权读取另一个工作区；需要别的目录时走协调器在既有授权范围内的交接。
5. **交接必须带 manifest，接收方必须独立复算。** 交接包记录源路径、字节数、sha256；接收方逐个复算后才可引用其结论，并公开声明“原始文件”与“交接副本”的区别。18/18 全部 MATCH 的复算归属 **B2 回合（普通执行配置）**；B5/B6 与后续回合只引用该结果，未重跑哈希复算。
6. **环境参数从具名启动回执取，不靠扫目录。** 三项 `KODER_*` 变量、当前工作区、输入文件路径、受控 Skill 升级哈希都写在具名回执里；为补教程去扫描安装目录既越界也拿不到更准的值。
7. **输出超限或进程状态不明时**：保留原回执、核查进程与已经发生的效果，结束该回合后**只接续剩余工作**；不得靠扩大输出、关闭保护或换工具重放来掩盖错误。回合在网络层失败（`ECONNRESET`、`API_IDLE_TIMEOUT`）时同理：没有工具写入就没有产物，按未完成续接。
8. **`learning_write` 契约**：`experience` 与 `complete` 的 `evidence` 必须是 `learning_read` 返回的来源对象数组，含 `document_id` 与 `excerpt_sha256`，**优先引用不可变的 node**；叙述性证据写进 `why` / `steps` / `pitfalls`。`decision` 与 `checkpoint` 会更新 memory/context，旧哈希随即失效；写完**读回**核对：写入失败不等于经验已沉淀。`complete` 不引用本项目 memory/context。
9. **失败回合必须保留。** 新成功只覆盖已复验的条件；原始失败回执（`original-failed/`）不删除、不覆盖。
10. **Agent 写下的经验仍是 `untested` 候选**，是否推广由独立验证决定，不因写进记忆就升级。
11. **长文档必须分页读到结尾**：`read_file` 的 `offset` / `maxBytes` 生效于 UTF-8 字节，按返回的 `nextOffset` 连续读到 `nextOffset=null` 才算读完。**不要用无变化替换（no-op `str_replace`）冒充读取**——那不产生任何读取回执。修复后的 `read_file` 仍保持 80KB 上限与工作区约束。
12. **pack 可能是缓存，恢复要重新观察磁盘**：`learning_read action=pack` 可能返回**旧节点内容**（B6 时点曾出现已写入 node30 但 pack 仍显示 node29）。写完 checkpoint 后要**单独再取一次 pack**，确认修订号与最新节点 id 已刷新（B7 回合实测：写完 checkpoint 后单独再取 pack，`projectRevision` 由 **35** 刷新为 **36**，最新节点变为 **node-36**）；要引用来源时用 `learning_read action=open` 打开不可变节点，取其返回的完整 source 对象作为 evidence。
