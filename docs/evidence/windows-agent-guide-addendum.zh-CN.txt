## 7. B14 回合的实际结果与不足

B14 的持久写入确实完成：`learning_write` 的 decision、checkpoint、complete 分别落到 revision 44、45、46，而非同为 46，主增补文件的写盘回执为 3543 字节、SHA256 `a3ee683b3da9b55816a509445348d520303fb03f2f7c51494ede8f577c5dab71`。但其最终 JSON 结果是 `status=unverified`、`exitCode=3`，问题记录为 `TASK_WRITING_LENGTH_OUT_OF_RANGE`，因此**不能计为验收通过**：写入发生不等于交付合格。

失败原因有两层，都要保留：

1. 检查器误把冻结指南的 33647 字节当作本增补的字数目标，又未识别 1000 至 1800 汉字区间；该缺陷已由协调器修正，并以三条复现用例先红后绿、52 项针对性回归验证。修正属于检查器侧，不是正文侧。
2. 正文侧的缺口仍存在：B14 增补正文实际只有 734 汉字，低于原定下限。检查器修好不等于稿件达标，本文件的扩写正是为补上这一段。

另有两项须如实记载：其一，B14 曾以 `personal-agent-growth` 作为 `skill_read` 的 id 调用，返回 `SKILL_NOT_FOUND`，随后改用准确 id `local:0de529bf577f688e11a2aa1e` 才读取成功；其二，B14 的主机原生进程退出回执与完整耗时未保存，`launcher_os_exit_code` 与 `launcher_wall_seconds` 为 null，故只引用原始 JSON 结果中的 3，不写成已取得的操作系统退出码，也不补写耗时。

B15 的宿主原生退出码确为 0，但其 checkpoint 后的 `learning_read pack` 返回 `LEARNING_CONTEXT_LIMIT`，且当时判定规则把最终字段置于内容之上；节点读取不等于 pack 恢复，B15 只完成记忆层收口、整体未验收，不按退出 0 抹去缺口。

## 8. 与 B14 的对账方法

对账只用 `review-inputs/b14-reconciliation.json` 中协调器实际的字段，不引用 manifest 的路径声明：

- `raw_result.status=unverified` 与 `raw_result.exitCode=3` 是最终判定；`taskDeliveryEvidence.disposition=delivered` 只说明文件写到了磁盘。
- `taskDeliveryEvidence.length.actual=734` 是正文真实汉字数，`required_range` 为 1000 至 1800；`target=33647` 是检查器误取的字节数，引用时须标注为检查器缺陷，不能当作目标字数。
- `persisted_revision` 记录的是 complete 的修订号 46，decision 与 checkpoint 分别为 44 与 45；`launcher_os_exit_code`、`launcher_wall_seconds` 为 null 说明退出回执与耗时缺失，只能保留未知。
- `failed_skill_read` 记录了那次 `SKILL_NOT_FOUND` 调用及其 toolCallId，必须与后续恢复一并写入总结，不能只写“本轮未新增工具失败”。

判读原则：`status=done`、写入回执存在、退出码为 0，任一单独出现都不构成交付验收；正文内容质量与检查器结果是两道独立必过的门槛，任何一道失败或未知都不能验收，不存在用最终字段覆盖正文问题的规则。

## 9. 可复用的恢复方法

1. **先修检查器，再修稿件**：长度类缺陷先确认计数字段是字节还是汉字、是否识别显式区间，避免把检查器故障误判成稿件故障。
2. **长文件按 nextOffset 续读**：英文参考文件用 `skill_read` 分页时，严格按返回的 `nextOffset` 继续，直到 `nextOffset=null`；`learning_read` 的分页结束字段才是 `next=null`。两者不要混用，也不要按字符数估算偏移。
3. **Skill id 必须精确**：先用 `skill_catalog` 取准确 id（如 `local:0de529bf577f688e11a2aa1e`），不要凭名称猜 id；`SKILL_NOT_FOUND` 后改用准确 id 成功恢复，这一失败与恢复都要如实写进总结。
4. **失败回合不重放**：B14 未保存原生退出回执，只引用现有 JSON 字段，不重跑命令、不编造耗时；缺失项标注为未知。
5. **改稿后必须读回**：写盘后用 `read_file` 完整读回，按实际内容核对字数与归属，再落 checkpoint；不要以写入成功代替内容正确。

本文件修订后仍需一次独立的长度复核（按汉字计数、1000 至 1800 区间），结论以实际读回内容为准。
