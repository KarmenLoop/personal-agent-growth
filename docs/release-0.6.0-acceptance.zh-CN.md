# 0.6.0 发布验收 — 2026-11-03

0.6.0 增加从任务提出未知问题、按机制检索经验、根据反馈重新规划以及可恢复的 Markdown 决策记录。原能力账本、宿主权限、模型配置与历史证据保留。本版交付可运行机制和有明确范围的 Agent 实测，不认证通用智能或精通。

## 实际运行了什么

四个新 Agent 在两个任务类型中产出了可用结果：先完成教学设计工作坊，再分别完成三种方法下的运维恢复手册。这些是实际模型回合、工具调用与父代理复核。它们编写的演练明确使用受控本地文件操作；演练子进程不冒充 Agent、生产事故或新的调度唤醒。

工作坊 Agent 首次检索没有命中，明确对齐问题结构词汇后才找到候选，并制作、执行了贡献者练习。独立审阅发现首版讲义把“收到任意观察后都重新规划”说得过宽；新版本正确区分了未知结果核实与已知结果后的规划。原版保留，提炼的经验仍为假设。

通用方案的运维 Agent 实际读取了**同一物理 Markdown 根目录**中的前任务 context、最新节点与当前状态，检索了新产生的教学设计经验，说明对应关系后用于运维恢复。其冷启动判断本来已包含避免重复执行等想法，不能把这些都归功于检索。复核发现一个负向检查先触发旧计划版本拒绝，不能证明它声称的待定状态拦截。修订脚本改用有效的当前版本计划，并核对准确错误原因；原错误归因与产物全部保留。新经验记录“拒绝原因必须隔离”，使用反馈记录“因果收益未定”。

最终用当前工具实际重放四个 Agent 的 Markdown：教学任务 revision 15／5 次动作；原方法 revision 6／2 次；通用方案 revision 12／4 次；领域方案 revision 6／2 次，全部返回 delivered 且无待定动作。父代理完整审阅了产物，并独立复现每个运维演练。[真实回放回执](evidence/adaptive-learning-20261103/agents.json)。

## 预先登记的探索性对比

三组使用相同运维任务和固定产物标准，分别测试原方法、通用经验迁移、领域专用规划；派发前已保存两份改法。每组实际完成整个任务，没有用检查器次数代替任务效果。

|---|---:|---:|---|
| 原方法 | 203.78 秒 | 418.05 秒 | 首次审阅通过 |
| 通用经验 | 242.64 秒 | 608.24 秒 | 修复检查归因；正确可用版本在 371.67 秒形成 |
| 领域规划 | 251.70 秒 | 512.44 秒 | 首次审阅通过 |

计时包含准备、编写、修正、审阅协调与收尾。并行运行和等待父代理审阅会影响比较，纯审阅阅读时长、原生 token、费用及服务端权重身份未知。教学任务的 359.09 秒仅覆盖初始化后的运行区间，记录接收前准备耗时未知，不可当成完整任务提速数据。

**本轮没有提升任何策略为全局默认。** 每组一次、费用未知，不满足统计提速或优越性结论；既有 PPC 比较门槛不变。原方法和两份候选都保留，没有启用改变过的组合，也没有虚构 Compose 运行。[比较结果与限制](evidence/adaptive-learning-20261103/comparison.json)。

## 修复与回归

复现并修复七类实现问题：存储封套超过可读大小、停止后耗时继续增加、规划额度死路、极小耗时导致非有限分数、日志满后无法核实待定动作、跨领域负面反馈被隐藏，以及未完成发布的临时文件占用最后核实容量。后来对软容量边界计时的一次疑虑，经核对实际源码后撤回，不额外计为缺陷。

本地公开仓库最终回归：**133 项通过、0 失败、0 跳过**，macOS arm64／Python 3.12.14，19.473 秒；运行前后 scripts、tests、tools 源码哈希一致。[完整输出](evidence/adaptive-learning-20261103/regression.stderr) · [命令与源码身份](evidence/adaptive-learning-20261103/regression.json)。

首轮全量回归因新版验收文档尚未存在保留 1 项失败、1 项准备错误；之后一次打包检查遇到尚未完成渲染的 SVG。后者保留工具返回的摘要记录，不伪称有单独的原始输出文件。各定向 RED/GREEN 输出保留在轨迹包中，失败不改写为成功。
