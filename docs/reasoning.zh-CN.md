# 思考、判断与学习为什么这样连接 · 0.4.3

[English](reasoning.en.md) · [架构](architecture.zh-CN.md) · [判断思维导图](diagrams/reasoning.zh-CN.svg)

## 1. 判断从目的和后果出发

“这是好还是不好”没有脱离目标的统一答案。先明确对谁有用、希望什么结果、哪些约束不能破坏、错误会造成什么后果，再设定评价标准。目标可能是解释、预测、选方案或交付产物；四种任务不能共用一个模糊的“看起来合理”。

判断卡至少记录：问题、用户目标、观察、假设、反对证据、未知、候选、质量标准、代价、当前选择、下一动作、预期观察及改判条件。它保存可公开复核的简短依据和行动轨迹，不要求模型隐藏思维链。

## 2. 最小颗粒度如何确定

从对象 → 组成 → 关系 → 输入 → 转换机制 → 输出 → 约束 → 失效方式展开。继续细分的条件是：这个子问题能区分候选、解释失败或改变下一动作。若细分只增加名词数量而不会改变任务，应停止。

例如“发动机为什么能动”先要确定讨论哪类发动机。以往复式内燃机为示意，可继续问：燃料与空气怎样进入、化学能怎样通过燃烧转为热、气体膨胀怎样对活塞做功、连杆与曲轴如何传递运动、排气和散热怎样维持循环。每条箭头都对应可核对的机制。这里是提问结构示例，不是具体机型的工程说明；电动机或其他发动机需要不同因果图。

解释任务可以停在机制足够清楚处；设计任务还要验证材料、负载、控制与实际约束。问题深度由用途决定，而非一律无限深挖。

## 3. 证据、解释与价值判断分开

| 类别 | 例子 | 下一动作 |
|---|---|---|
| 观察 | 检查器返回退出码 2，阶段为 read_archive | 保存输入路径与原始错误 |
| 解释 | 可能是路径改变，不一定是归档损坏 | 检查实际文件及目录映射 |
| 预测 | 正确定位后，同一包应可完成一致性检查 | 在修正前记录预测 |
| 价值判断 | 交付优先保证可恢复，再优化耗时 | 对照用户目标与固定质量标准 |
| 未知 | 尚未在第二宿主实际运行 | 保留 NOT_RUN，不借本机结果外推 |

来源冲突时比较时间、原始性、适用对象和方法，不按网页数量投票。同一原文的转载与摘要只算一个来源；公开人物的表达可以形成有出处的工作方法假设，不能把评价、语气或院校背景当作其真实内心的证据。

## 4. 决定研究、试验、执行还是提问

先问：缺少什么信息？不同答案会改变哪个动作？能否通过现有文件或工具获得？最小试验是什么？获得信息的成本是否超过可能避免的损失？这是排序原则，不把未经测量的主观分数冒充客观概率。

公开事实自行查证；可重复的技术不确定性做小试验；前置已满足则执行；只有用户独有的目标冲突、权限扩大或预算选择才提问。等待答复时推进独立部分，记录真正依赖答案的分支。主动性体现在提出可验证选项并完成工作，而不是频繁弹窗。

## 5. 预习、补课、复习各解决什么问题

| 环节 | 为什么做 | 怎么做 | 怎样判断有效 |
|---|---|---|---|
| 预习 | 降低下一动作的不确定性 | 从下一用途提出问题，查一手资料，写预测 | 后续任务实际使用该知识，且改变了动作 |
| 预演 | 在低成本环境发现潜在失败 | 隔离副本或只读变式，保留预计结果 | 找出会影响正式方案的差异 |
| 补课 | 修复已出现的能力缺口 | 保留原失败、区分原因、补知识或改方法 | 原任务重新验证，旧失败没有被删掉 |
| 复习 | 检查能否迁移及何时失效 | 换路径、顺序、边界或新任务再应用 | 正例可用、反例拒绝、适用边界明确 |

预习后没有实际用途的知识保留为候选；复述以前的答案不算复习通过。重复失败触发旧问题重新打开，而不是产生另一条内容相同的“新经验”。

## 6. 完整任务轨迹：交接包复习

以下重构历史验收中的机制，具体执行证据见[历史验证](validation.md)与[递归实测](recursive-improvement-trial.md)；并非本次新增 Agent 运行。

1. **目标：** 接收方在不同位置能继续检查交接包。完成依据同时包含包一致性、资源可读和搬迁后可用。
2. **原判断：** 资源仍在包目录内、当前机器可读，可能足以证明可搬迁。先保存此预测。
3. **自主发现缺口：** ZIP/manifest 检查只证明内容一致，不证明 Markdown 引用与符号链接在新位置有效。
4. **预习：** 针对相对路径、绝对符号链接及目录链接补知识；不无边界研究所有文件系统。
5. **Probe：** 在隔离副本移动整个包，确认旧位置不再可用，再读取引用。绝对链接暴露失败；后续目录链接变式又发现间接依赖。
6. **改判：** 当前可读不能推出搬迁可用；“目标仍在包内”也不足以排除间接依赖。依赖此判断的验收项重新打开。
7. **补课与修复：** 修正资源判定方法，保留两次失败与输入身份，复跑原案例和变式。
8. **联系用户：** 这类修复在授权范围内可自行解决，因此先完成，在结果中说明变化，无需新开对话。
9. **调整 skill：** 将“归档一致、资源可读、搬迁后可用分别验收”写入候选方法，保留回滚点；只有实际验证支持的范围才启用。
10. **复习接续：** 新宿主读最新修订、复用检查器、写回变式结果；有具体间隔复习用途时才登记后续。

断点对应修复：只存退出码 → 绑定输入与阶段；只存报告 → 将复习回写到可检索索引；只改规则 → 必须复测；只列路径 → 验证接收者实际读取。

## 7. 将经验转为元能力

单任务教会“这类包如何检查”；跨任务层继续问“为什么总选错验收层”“经验加载为何过多”“提案是否重复堆提示词”。把机制抽象成新假设，在不同领域实跑，再用原先成功任务做回归。

例如完整任务实测把软件交接验收与 NASA 数据分析放在同一冻结组合中。批量检查在第一类任务有用，科学数据转换需要不同领域工具；共同方法是输入归属、独立校验、完整失败计费与简洁交付。组合版 token 减少但总耗时增加，促使下一提案关注修复成本而非只数工具调用。数字与限制见[跨领域报告](cross-domain-trial.zh-CN.md)。

## 8. 商业、人物与事件研究如何套用

创业仅是方法示例：先明确领域、用户约束、交付物，再主动查近期企业、融资与产品一手资料。融资是资本信号，不能直接推导有付费需求或能盈利。比较客群、触发场景、替代方案、获客与单位经济假设，再设计可证伪访谈或小试验。

人物研究区分本人公开陈述、已观察决策、第三方评价与系统推断；认知框架必须附来源和反例。事件研究先固定时间线、起因、过程、结果、参与者与信息缺口；因果归因需要替代解释，评价标准要说明受影响主体与时间尺度。

所有领域复用同一骨架：目的 → 分解 → 证据 → 假设 → 可区分试验 → 决定 → 观察 → 修正。领域知识改变具体内容，不替代这个闭环。
