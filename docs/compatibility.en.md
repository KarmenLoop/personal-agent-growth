## Separate Koder Markdown candidate

The [sanitized public evidence](evidence/koder-markdown-candidate-20261027.json) was generated after reading retained test output and receipts. Source commit: `fa854e88f5a7325399f9a2f32950848737cdf1d9`, macOS arm64. Private source and full private traces were not uploaded.

- Learning checks: 30/30 passed, covering recovery, retrieval, correction propagation, invalid summaries, overflow, same-minute nodes, catch-up, actual process interruption, and concurrent writes.
- Historical pre-repair candidate: 1454 tests, 1388 pass, 31 fail, 14 cancelled, 21 skipped. Baseline: 1425 tests, 1358 pass, 31 fail, 15 cancelled, 21 skipped. Zero candidate-only nonpassing names does not make the suite green. File timeouts change discovery totals, so their difference is not a count of added cases.
- Five actual process stages: initialization 935 ms, first execution 4777 ms, new-process recovery 2198 ms, completion 297 ms, new-project reuse 533 ms. Different workloads do not establish a speed improvement.
- A real 60000 ms idle callback updated the daily report within 61815 ms observed time, establishing only an in-process timer while open.
- A scripted acceptance provider exercised the native tools without paid/remote model requests. It does not establish independent learning quality; tokens/cost remain unknown.

The candidate covers `learning init/status/project/checkpoint/resume/open/search/experience/complete/observe/decision/tick/daily/weekly/consolidate/on/off`, native `learning_read/learning_write`, Markdown transactions, read sets, a 4000-token cap, and due-work processing. This lists candidate capabilities; installing this skill does not install those native commands.

## What would support stronger claims

For Windows Agent continuity, recover the original directory and receipts, have actual Koder read/write, then have an actual Cursor model turn read the same revision, review, and write back. Check both artifacts and read sets. Keep this branch pending while the device is unavailable; independent documentation can still publish.

Cross-device claims need content identity, conflict handling, mappings, and permissions checked on both ends. No-new-message operation needs real host events plus execution/acceptance/stopping receipts. Efficiency needs full-task quality, elapsed time, native usage, and optimization overhead rather than call counts.

Public summaries retain source hashes and scope but are not the full private trace. Repository tests are independently rerunnable; historical maintainer device reports are a different form of evidence.
